# Хрустальный — лендинг аудита концепции + лидоген (сайт + Telegram-бот)

Один сервис на **FastAPI**: раздаёт лендинг и юридические страницы, принимает
заявки `POST /api/lead` и держит **Telegram-бот на webhook**. На старте лиды
уходят карточкой в группу продаж (без таблицы) — MVP-хранилище. Полный контур
152-ФЗ: политика, согласие, лог факта согласия с каждым лидом.

> Дизайн и тексты лендинга, а также тексты бота — из брифа, не меняются.
> Палитра navy/белый, шрифт Manrope, обращение на «вы», без эмодзи.

## Структура

```
app/
  main.py        # FastAPI: статика + /api/lead + webhook + жизненный цикл бота
  config.py      # конфигурация из ENV
  leads.py       # схема, валидация, анти-спам, save_lead() (интерфейс хранилища)
  legal.py       # фиксация факта согласия (152-ФЗ)
  telegram.py    # карточки лидов, кнопки статуса, /start-воронка, тексты бота
web/
  index.html     # лендинг (форма → /api/lead, honeypot, cookie-баннер, Я.Метрика)
  privacy.html   # /privacy + согласие #consent (152-ФЗ)
  cookie.html    # /cookie — политика по cookie
  assets/        # картинки (вынесены из base64; HTML ~80 КБ)
Dockerfile  railway.json  requirements.txt  .env.example
```

## Маршруты

| Метод | Путь | Назначение |
|------|------|-----------|
| GET  | `/` | лендинг (с инъекцией счётчика Я.Метрики из `YM_ID`) |
| GET  | `/privacy`, `/privacy#consent` | политика и согласие |
| GET  | `/cookie` | политика cookie |
| GET  | `/assets/*` | картинки |
| GET  | `/healthz` | проверка живости |
| POST | `/api/lead` | приём заявки с сайта |
| POST | `/telegram/<TELEGRAM_WEBHOOK_SECRET>` | webhook Telegram |

`POST /api/lead` тело: `{name, phone, region, stage, comment?, consent, hp, page_url}`.
Валидация на сервере: имя ≥2, телефон РФ, `consent==true`, `hp` пустой; rate-limit по IP.
Honeypot-заявкам отвечаем `{ok:true}`, но не сохраняем.

## Переменные окружения

См. `.env.example`. Ключевые:

| Переменная | Назначение |
|-----------|-----------|
| `TELEGRAM_BOT_TOKEN` | токен из @BotFather — **только в ENV**, не в репозиторий |
| `TELEGRAM_SALES_CHAT_ID` | группа продаж для заявок (`-5481376613`) |
| `ADMIN_USER_ID` | админ-команды бота только этому ID (`989604210`) |
| `TELEGRAM_WEBHOOK_SECRET` | секрет пути вебхука (`openssl rand -hex 24`) |
| `PUBLIC_BASE_URL` | публичный адрес сервиса для `set_webhook` (на Railway — авто из `RAILWAY_PUBLIC_DOMAIN`) |
| `SET_WEBHOOK_ON_STARTUP` | ставить ли webhook при старте (по умолчанию `true`) |
| `ALLOWED_ORIGIN` | домен лендинга (CORS) |
| `YM_ID` | счётчик Яндекс.Метрики (опц.); цель `lead_submit` |
| `CONSENT_VERSION` | версия текста согласия (`2026-06-24`) |

## Локальный запуск

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # заполнить локальные значения (можно без токена — сайт поднимется без бота)
export $(grep -v '^#' .env | sed 's/#.*//' | xargs)   # или используйте python-dotenv/направление ENV хостинга
uvicorn app.main:app --reload
```

Откройте http://localhost:8000 — форма отправляет в `/api/lead`. Без
`TELEGRAM_BOT_TOKEN` бот отключён, карточка в Telegram не уходит (в логах —
предупреждение), остальная логика работает.

## Telegram-бот

- Профиль (имя/описание/команды/картинка) задаётся в @BotFather — см.
  `botfather-setup.md` из выгрузки. Команды бот также регистрирует сам при старте.
- Команды: `start`, `audit`, `case`, `contact`. Тексты — из брифа (раздел 6).
- Воронка «Разобрать мой проект»: регион → стадия → имя → телефон → согласие →
  лид уходит карточкой в группу тем же `save_lead()`.
- Карточка лида в группе содержит инлайн-кнопки **Взять в работу / Квалифицирован
  / Отклонить** — фиксируют статус прямо в сообщении.
- Админ-команда `/webhookinfo` доступна только `ADMIN_USER_ID`.

## Превью на GitHub Pages (без бэкенда)

Пока не подключён домен и серверный деплой, лендинг публикуется статикой на
GitHub Pages — как публичное превью. Бэкенд (`/api/lead`, бот) при этом не
работает: форма обращается к `window.__API_BASE` (по умолчанию пусто), и при
недоступном API показывает контакты (телефон/Telegram).

Сборка статики: `python3 scripts/build_static.py _site` — переписывает корневые
пути на относительные (работает и на `user.github.io/repo/`, и позже на домене).
Публикацию выполняет workflow `.github/workflows/pages.yml`.

**Включить один раз:** Settings → Pages → Source → **GitHub Actions**. После
этого пуш в ветку публикует сайт; адрес появится в Settings → Pages и в логах
workflow. Если окружение `github-pages` ограничивает ветки — разрешите текущую
ветку (Settings → Environments → github-pages) или слейте её в `main`.

**Когда поднимем бэкенд:** задать репозиторную переменную `API_BASE`
(Settings → Secrets and variables → Actions → Variables) на адрес API
(напр. `https://audit.hrustalni.com`) и при необходимости `YM_ID` — форма на
превью начнёт отправлять заявки на бэкенд (нужен CORS: добавить домен Pages в
`ALLOWED_ORIGIN`).

## Деплой бэкенда (Railway / Docker)

> ⚠️ По брифу деплой и `set_webhook` выполняются **после подтверждения**.

1. Создать сервис из репозитория (`railway.json` → сборка по `Dockerfile`).
2. Прописать ENV из таблицы выше (секреты — только здесь, не в репозитории).
3. Домен: поддомен (напр. `audit.hrustalni.com`) → custom domain → DNS CNAME.
   Прописать его в `ALLOWED_ORIGIN` и `PUBLIC_BASE_URL`, HTTPS — автоматически.
4. Первый деплой можно сделать с `SET_WEBHOOK_ON_STARTUP=false`. Когда всё
   проверено — выставить `true` (или дёрнуть `setWebhook` вручную) и проверить
   `/webhookinfo`.
5. End-to-end тест: отправить форму на сайте и пройти воронку в боте — карточки
   должны прийти в группу `-5481376613` за <5 сек.

## 152-ФЗ и локализация ПДн

- С каждым лидом фиксируется факт согласия: `consent_version`, дата, IP,
  user-agent, источник — в локальный лог `data/consent_log.jsonl` (вспомогательный)
  и в карточку заявки.
- **Решение по хранению (требует согласования):** на старте лиды живут только в
  Telegram (быстрый запуск). Railway размещён **вне РФ**, поэтому для строгого
  152-ФЗ (локализация ПДн граждан РФ на территории РФ) в фазе 2 нужно подключить
  хранилище в РФ: БД на РФ-хостинге (`DATABASE_URL`) либо согласованный вариант с
  Google Sheets. Точку расширения см. в `app/leads.py::save_lead()` — добавляется
  новый sink без правок остального кода.
