# Wordstat-анализ рынка загородной недвижимости Читы (Карповка)

Инструментарий сбора частотности Wordstat по семантическому ядру проекта и
переноса в отчёт `Wordstat_Chita_analiz.xlsx`.

## Статус

Код доведён до рабочего состояния и проверен end-to-end на синтетических данных
(перенос + пересчёт формул + скан ошибок — чисто). **Реальный сбор не выполнен**:
из текущего окружения нет доступа к API (два блокера ниже). Как только доступ
появится — весь прогон это 3 команды.

### Блокеры реального сбора

1. **Egress-политика.** Хост `searchapi.api.cloud.yandex.net` закрыт egress-политикой
   окружения (шлюз отвечает `403` на `CONNECT`). Нужно добавить хост в allowlist
   окружения либо запускать в окружении со свободным HTTPS-egress.
2. **Ключи.** Переменные `YC_API_KEY` и `YC_FOLDER_ID` не заданы. Передавать
   только через ENV — в файлы/логи/коммиты ключ не пишется.

## Порядок запуска

```bash
pip install -r requirements.txt
export YC_API_KEY=...        # только ENV, не коммитить
export YC_FOLDER_ID=...

python collect.py verify-regions   # ШАГ 2: найти ID Читы/Забайкалья/Иркутска -> REGIONS
python collect.py collect --dry-run # ШАГ 3: объём и оценка времени
python collect.py collect           # ШАГ 4: сбор -> raw_data.json (стоп при >5% ошибок)
python to_xlsx.py Wordstat_Chita_analiz.xlsx   # ШАГ 5: лист «Данные» + «Динамика»
python verify.py Wordstat_Chita_analiz.xlsx    # ШАГ 6: пересчёт формул + доклад
```

## Что было доработано в коде (ШАГ 1 / 5)

Схема ответа API не проверялась вживую (нет доступа), поэтому имена полей взяты
терпимым перебором с единственной точкой правки после первого реального JSON:

- `collect.py` — сохраняет **полный сырой ответ** для частотности (а не только
  число), извлекает частотность через `extract_total()`, помечает «ниже порога»,
  и **останавливается при доле ошибок > 5%** (ШАГ 4).
- `to_xlsx.py` — правило **«меньше 10 → 0»** (раньше такие строки пропускались);
  реализован перенос **помесячной динамики** на лист «Динамика» (регион Чита,
  сопоставление по фактическим меткам месяцев и заголовкам фраз, а не по порядку).
- `verify.py` — ШАГ 6 без офисного пакета: пересчёт формул движком `formulas`
  (аналог headless-LibreOffice), проверка `#REF!/#DIV/0!/#VALUE!` и печать доклада.

### Точки, которые надо подтвердить по первому реальному JSON (ШАГ 1)

- имя поля общей частотности в `topRequests` (гипотеза `totalCount`) —
  `collect._TOTAL_KEYS` / `to_xlsx._NUM_KEYS`;
- структура ряда `dynamics` (имена периода/значения, формат даты, диапазон 24 мес) —
  `to_xlsx.extract_series` / `norm_period`, и раскомментировать даты в `collect.py`;
- как выглядит «ниже порога показа» (сейчас: успех без числа → 0);
- имена полей расширения (`associations`) — `verify._EXP_*`;
- реальный лимит rps → при необходимости поднять `RATE_DELAY`.

Семантическое ядро `keywords.py` не менялось. Формулы и структура листов xlsx
не менялись — заполняются только значения.
